# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

BBFerm is a local-first homebrewing app running on a Raspberry Pi Zero 2 W (512 MB RAM). The design docs in `docs/` are the source of truth; read `docs/architecture.md` and `docs/decisions.md` before making structural changes.

## Commands

Node 24 (`.nvmrc`), pnpm 10. Run from the repo root.

```sh
pnpm typecheck && pnpm test && pnpm build      # everything, topologically ordered
pnpm dev:store | pnpm dev:collector | pnpm dev:web
pnpm --filter @bbferm/collector exec vitest run test/decode.test.ts -t "Tilt Pro"   # single test
pnpm --filter @bbferm/web start                # serve the production web build (127.0.0.1:3000)
```

Local dev needs each service's `.env` copied from its `.env.example` (`src/services/store/server`, `src/services/collector`, `src/apps/web`). The collector replays fixtures from `test/fixtures/advertisements.json` by default; BLE (`COLLECTOR_SOURCE=bluez`) is not implemented yet.

## Architecture

Three independently deployed services; the browser only ever talks to web:

```text
browser ──▶ web (TanStack Start, SPA mode: UI + BFF) ──▶ store (Fastify, sole SQLite owner) ◀── collector (Tilt BLE)
```

- Web deploys must never restart the collector (BLE advertisements missed while it's down are lost forever).
- Only Store may open SQLite or import a DB driver. Store and collector are loopback-only; the web server binds `127.0.0.1` (srvx defaults to all interfaces, so keep `--host` in the start script).
- Store currently uses an in-memory repository behind `MeasurementRepository`; the SQLite driver and BLE library are deliberately unchosen until tested on the Pi.

### Contract ownership (ADR-009)

Each API provider owns and publishes its schemas; there is no shared contracts package.

- Store publishes `@bbferm/store-contract` (`src/services/store/contract`), consumed by the BFF and collector. It must depend only on `zod` and `@bbferm/domain` so consumers never install Fastify or the DB driver.
- The BFF owns browser schemas in `src/apps/web/src/server/*.schemas.ts` and maps Store DTOs to them in `*.functions.ts`. UI code must never import `@bbferm/store-contract`; Store shapes and raw sensor payloads must not reach the browser.
- Shared value types (Id, UtcTimestamp, SpecificGravity, MeasurementSource, QualityFlag) live in `@bbferm/domain`.
- `/internal/v1` must stay backward compatible because services deploy independently. Adding fields is safe; removing or renaming needs `/internal/v2`.

### Web / BFF conventions

- `*.server.ts` modules are server-only and start with `import '@tanstack/react-start/server-only'`; Store URL and token are read there from `process.env`. Never use `VITE_*` for secrets.
- `*.functions.ts` export `createServerFn` wrappers (input validation uses `.validator(...)` in this Start version). `*.schemas.ts` must stay client-safe.
- Server functions are CSRF-protected by Start: requests without same-origin `sec-fetch-site`/`origin` headers get 403.
- Store auth: separate bearer tokens per caller (`STORE_WEB_TOKEN`, `STORE_COLLECTOR_TOKEN`), each restricted to its own endpoints.

## Gotchas

- **Workspace package resolution:** packages export TS source under the custom `@bbferm/source` condition and compiled `dist/` otherwise. Vite (`vite.config.ts`), vitest (`vitest.config.ts` per package) and `tsx --conditions=@bbferm/source` use source; built services run `node dist/main.js` and need `pnpm build` of their dependencies first. A new package needs the same `exports` shape, and a new consumer needs the condition configured.
- **PWA service worker:** vite-plugin-pwa normally writes `sw.js` before Start prerenders `/_shell.html`. The `pwaAfterStartBuild` plugin in `src/apps/web/vite.config.ts` regenerates it in a `buildApp` post hook so the shell is precached as the navigation fallback. It relies on plugin internals; after upgrading Start or vite-plugin-pwa, verify `dist/client/sw.js` contains `_shell.html` and `createHandlerBoundToURL("/_shell.html")`. Never runtime-cache `/_serverFn/` or `/api/`.
- **Pi deployment:** never copy macOS `node_modules` or native `.node` modules to the Pi; native deps must be installed for Linux ARM64.
- **Measurements:** the collector generates the measurement `id` once and reuses it across retries (it's Store's idempotency key). Store receive time is `receivedAt`; Tilt packets have no trustworthy sample timestamp, so `observedAt` stays null. Temperatures are stored in Celsius, gravity as a decimal SG (`1.048`). Raw values are preserved alongside normalized ones; suspicious readings are kept with `qualityFlags`, not dropped.
- `src/apps/web/src/routeTree.gen.ts` is generated by the router plugin; don't edit it by hand.
